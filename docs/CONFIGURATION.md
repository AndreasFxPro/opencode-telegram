# Configuration

Default paths:

```text
~/.config/opencode-telegram/config.json
~/.config/opencode-telegram/secrets.json
~/.local/share/opencode-telegram/hub.db
~/.local/share/opencode-telegram/node.db
```

Override the config path with `OPENCODE_TELEGRAM_CONFIG`.

See [`config.example.json`](../config.example.json). `secrets.json` is generated by setup and contains only the mode-relevant subset of:

```json
{
  "telegramBotToken": "hub only",
  "localPluginSecret": "per machine",
  "nodeId": "public node identity",
  "nodeCredential": "node only"
}
```

## Authorization

`viewer` can use status commands. `approver` can answer pending permissions/questions. `owner` can change chat-wide mute state and is reserved for administrative bot operations. Both the chat and Telegram user must be allowlisted. Unknown identities receive no internal details.

## Notification Defaults

- Permission, question, and errors: enabled.
- Completion: enabled after 20 seconds.
- Root sessions only for completion.
- Branch/model/agent metadata: enabled when natively available.
- Final preview: disabled.
- Remote prompt: disabled and not exposed by the current alpha CLI.

The schema reserves one optional `threadId` per authorized chat, allowing a global forum topic without changing message identity. Per-node/project topic policy is planned.

## Precedence

Current alpha implements global configuration plus a per-TUI runtime mute command. The intended future precedence is session runtime override, project, node, then global. Unsupported scopes are not silently accepted by the strict schema.
